## 日常开发规范

### Git 分支策略

```
main          ← 生产分支，仅通过 PR 合并
├── develop   ← 开发分支
│   ├── feat/phase1-scaffold    ← W1 脚手架
│   ├── feat/phase1-auth        ← W2 认证
│   ├── feat/phase1-tutor       ← W3 AI导师
│   ├── feat/phase1-quiz        ← W4 题库
│   ├── feat/phase2-rag         ← W5 RAG
│   └── ...
└── release/v1.0
```

### Commit 规范
```
feat: AI导师首页对话功能
fix: 修复 LaTeX 公式渲染问题
chore: 更新依赖版本
docs: 补充 API 文档
```

### 每日开发流程
1. `git checkout -b feat/xxx` 创建特性分支
2. 编写代码 + 本地测试
3. `git commit` 提交
4. PR → review → merge 到 develop

### 代码审查清单
- [ ] TypeScript strict mode 无错误
- [ ] Python mypy 类型检查通过
- [ ] 新 API 端点有请求/响应模型验证
- [ ] 前端新组件遵循 DESIGN.md 令牌
- [ ] 用户输入做了适当的转义/验证
- [ ] 无硬编码密钥（使用环境变量）
